## 1. Start with the email account

Use a dedicated or carefully protected email address for financial accounts. Give it a unique password and phishing-resistant authentication if the provider supports passkeys or hardware security keys. Remove obsolete recovery addresses and phone numbers.

An exchange can have excellent security and still be reset through a compromised inbox. Do not forward exchange mail to a weaker account, and do not store seed phrases or authenticator backups in that same mailbox.

## 2. Use a password manager, not a memorable pattern

Generate a long, unique password and save it in a reputable password manager. The benefit is not merely length: the manager refuses to autofill on look-alike domains, which can expose phishing pages. A password variation such as `Summer2026-WhiteBIT` is still a reused pattern and can be guessed after another breach.

Never share the password with an assistant, “account manager,” or remote-support tool. WhiteBIT support does not need it to investigate a problem.

## 3. Choose passkey or authenticator 2FA

WhiteBIT documents passkeys and time-based authenticator codes. Both are stronger than password-only access. Passkeys can resist phishing because they are bound to the real domain; authenticator apps are widely supported and work offline, but users can still be tricked into typing a code into a fake site.

Avoid SMS as a primary second factor where better options exist. Whichever method you choose, create a recovery plan and store backup material offline in a place a thief cannot access together with your laptop or phone.

## 4. Turn on the anti-phishing code

Set a phrase that will appear in legitimate WhiteBIT system emails. Its absence is a reason to stop, not a reason to click faster. The code helps distinguish official mail from bulk phishing, but it does not make every message containing the code safe forever.

Navigate through a saved bookmark or the partner link rather than clicking urgent email buttons. Treat “account frozen,” “bonus expiring,” and “withdrawal pending” messages as prompts to open the official site independently.

## 5. Audit sessions and devices

Review active sessions after setup and on a schedule. Close anything you do not recognize and remove old phones or browsers. Use a personal device with current security updates, full-disk encryption, and a screen lock. Do not access an exchange from a shared office computer or borrowed phone.

A VPN can protect traffic on untrusted Wi-Fi, but it cannot rescue a malware-infected device or a fake domain. The priority order is patched device, verified site, strong authentication, then safer network transport.

## 6. Restrict withdrawals

Use address management or whitelisting for known destinations if it fits your workflow. Name entries clearly and verify the receiving wallet on its own trusted screen. Clipboard-stealing malware can replace an address between copy and paste, so compare characters and use a small test.

Be aware that security changes can trigger temporary withdrawal restrictions. That inconvenience is intentional. Do not disable controls immediately before a large transfer; plan changes days in advance.

## 7. Design recovery before you need it

Write down what happens if your phone is lost, your authenticator is unavailable, or your email is locked. Keep the necessary recovery material offline and tell no one the full set of locations. If you use a hardware wallet, its seed phrase is never entered into WhiteBIT, a website, a support chat, or a computer file.

Recovery that exists only in your memory is fragile. Recovery stored beside the device is not independent. The goal is a process you can execute under stress without improvising.
