## Before a crypto deposit

Open the deposit page for the exact asset on WhiteBIT. Note the supported networks, minimum deposit, required confirmations, and whether a memo or tag appears. Then open the sending platform and verify it supports the same network.

Do not select a cheap network merely because both interfaces show the same token ticker. USDT on Ethereum, Tron, and other networks represents different routes. Both ends must match exactly.

## The crypto deposit checklist

1. Confirm the WhiteBIT account and KYC status are ready.
2. Check the WhiteBIT system page for deposit availability.
3. Select the asset and network on WhiteBIT first.
4. Copy the address using the interface; do not retype it.
5. Include the memo/tag when shown.
6. Compare the first and last address characters after pasting.
7. Send a small test amount above the minimum.
8. Track the transaction ID in the relevant explorer.

Only reuse the route after the test is credited and the address remains unchanged.

## Before a crypto withdrawal

Generate the receiving address inside the destination wallet or exchange. Verify the device and app are genuine, the wallet supports the asset, and the selected network is enabled. On a hardware wallet, confirm the address on the trusted device screen—not only on the computer.

Review WhiteBIT's live withdrawal fee and minimum. A test that falls below the receiving platform's deposit minimum can arrive on-chain but never be credited, so check both sides.

## The crypto withdrawal checklist

1. Check withdrawal availability and any maintenance notices.
2. Confirm asset, network, address, and memo/tag.
3. Review fee, minimum, and final amount the recipient will receive.
4. Use an address-book entry only after re-verifying it.
5. Send a test to a new destination.
6. Confirm the test in the destination balance and explorer.
7. Repeat the address check before the main transfer.
8. Save the transaction ID and a note describing its purpose.

Pause if the platform asks you to disable security controls or if anyone pressures you to “unlock” a withdrawal by sending more crypto.

## Fiat deposits and withdrawals

Fiat routes introduce a different set of checks: account holder name, bank details, reference field, payment-provider terms, processing time, and currency conversion. Use a bank account in your own name where required and copy the reference exactly.

Compare the net amount, not only WhiteBIT's displayed fee. Your bank or card issuer may add charges. EU users should also confirm they are using the appropriate WhiteBIT EU flow and a currently supported payment route.

## What to do when a transfer is delayed

First find the transaction ID. If no transaction ID exists, the sending platform may still be processing the withdrawal. If the transaction is on-chain, check confirmations and the destination's crediting requirement. Review WhiteBIT's system page for maintenance or network issues.

Contact official support with the transaction ID, asset, network, amount, time, and destination address. Never send a seed phrase, private key, authenticator code, or remote-access invitation. Those details do not help legitimate support trace a transfer.

## The test-transfer rule

A test transfer adds one fee and removes several unknowns. It confirms network compatibility, destination control, minimum handling, address correctness, and your ability to repeat the process. For a first route or a large amount, that is cheap insurance.

If a network's fees make a test economically unreasonable, slow down and choose another supported route rather than using urgency to justify risk.

## FAQ

### Can WhiteBIT recover a transfer sent on the wrong network?

Recovery may be impossible and depends on the exact technical situation. Prevention—matching both ends and testing—is the reliable strategy.

### Why is a memo or tag important?

Some networks use one shared address plus a memo/tag to identify the receiving account. Omitting it can prevent automatic crediting.
