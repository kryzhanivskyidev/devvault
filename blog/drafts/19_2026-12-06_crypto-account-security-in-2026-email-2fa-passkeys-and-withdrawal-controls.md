## Email is part of the exchange account

Use a unique password and strong authentication on the email account. Remove stale recovery options, review forwarding rules, and keep exchange mail out of shared inboxes. A dedicated address can reduce exposure, but secrecy is not a substitute for controls.

If the email provider supports passkeys or hardware security keys, use them. Protect recovery codes offline.

## Password managers prevent more than reuse

A password manager generates unique credentials and associates them with the correct domain. That can reveal a phishing site when autofill refuses to appear. Do not override the warning by manually pasting the password.

Choose a strong master password and protect the manager with a passkey or hardware key where possible.

## Passkey versus authenticator app

Passkeys are domain-bound and can resist credential phishing. Authenticator apps generate time-based codes and work broadly, but a fake site can ask the user to relay a current code. Both are stronger than password-only login.

Avoid SMS when better options exist, especially for accounts tied to a publicly known phone number. Build recovery before switching methods.

## Anti-phishing and verified navigation

Set the exchange's anti-phishing code if available. Save a bookmark to the official domain and use it instead of search ads. Treat unexpected messages as untrusted even when they use the brand's logo and urgent language.

Official support never needs a seed phrase, private key, password, or authenticator code. Anyone asking for those is attacking the account.

## Sessions, devices, and API keys

Review active sessions monthly and after travel. Revoke unknown devices and old browsers. Audit API keys, remove unused integrations, and avoid withdrawal permissions. Restrict by IP where supported and store secrets outside source code.

Keep the operating system, browser, and extensions lean. Every extension is code with access to part of the browsing environment.

## Withdrawal controls

Whitelist known addresses, verify new destinations independently, and expect temporary holds after security changes. Use a test transfer and confirm address characters after pasting. For large withdrawals, use a quiet time and a second-person review if possible.

Balance limits matter too. Security is stronger when one compromised account cannot expose the entire portfolio.

## Recovery and incident response

Write a one-page plan: official support link, email recovery, device wipe, session revocation, wallet migration, and who to contact. Keep it offline or encrypted. Practice the non-destructive steps.

After a suspected compromise, move from a clean device. Changing a password on an infected machine can hand the new credential to the attacker.

## FAQ

### Are passkeys better than 2FA codes?

Passkeys offer strong phishing resistance when implemented correctly. Authenticator codes remain useful but can be phished. Recovery and device security matter for both.

### Does a VPN secure my exchange account?

It protects network transport on untrusted connections. It does not stop phishing, malware, or approval of a malicious withdrawal.
